# Community Agent：社区第一版实现方案

日期：2026-09-16。状态：实施中。本方案替换原学籍 Agent 设计；旧系统测试结果不代表本方案已验收。

实施进展（2026-09-17）：阶段 0、1 已完成，独立底座、注册登录、草稿与帖子、标签、版本历史和软删除已落地；阶段 2–5 待实现。当前结果见 [阶段 1 实施与验收说明](community-phase1.md)，账号底座见 [阶段 0 说明](community-phase0.md)。

## 1. 产品目标与范围

做一个面向技术学习与项目交流的社区。用户发布笔记、提问、分享项目；助手帮助整理资料和查找社区中已有的讨论。技术学习是首批演示主题，不做特定学校的业务系统。

第一版要跑通：**注册登录 → 发布与互动 → 上传资料生成私有草稿 → 人工确认发布 → 用自然语言检索社区内容并给出引用。**

| 第一版包含 | 明确不包含 |
| --- | --- |
| 注册、登录、退出、普通用户/管理员 | 第三方登录、复杂角色系统、组织空间 |
| Markdown 帖子、标签、草稿、编辑历史、软删除 | 实时协作编辑、复杂富文本编辑器 |
| 一级评论、点赞、收藏、自己的内容列表 | 多层评论、关注关系、私信、积分 |
| 时间排序的信息流、标题/正文/标签搜索 | 个性化推荐、热门算法、独立搜索集群 |
| 举报与管理员隐藏/恢复内容、停用账号 | 自动封禁、自动审核决策 |
| TXT/Markdown/文字 PDF 生成帖子草稿 | 扫描/OCR、手写、多格式全覆盖、自动发布 |
| 社区问答、引用原帖、本人帖子的修改建议 | 任意 SQL、跨站搜索、自动操作他人内容 |

扫描 PDF 检测到无可提取文字时明确提示暂不支持，不能悄悄生成空草稿。旧 OCR 能力不作为第一版依赖；DOCX 和扫描件在样本评测后再接入。

## 2. 页面与用户流程

| 页面 | 内容与主要操作 |
| --- | --- |
| 社区首页 | 最新帖子、标签筛选、关键词搜索、发布入口 |
| 帖子详情 | 正文、作者、时间、标签、点赞/收藏、评论、举报 |
| 编辑页 | Markdown 编辑与安全预览、保存草稿、发布、版本冲突提示 |
| 我的内容 | 已发布、草稿、收藏、资料处理任务 |
| 资料导入页 | 上传、解析状态、原文定位、生成草稿、确认采用 |
| 社区助手 | 提问、回答、引用卡片、失败或证据不足提示 |
| 管理页 | 举报列表、隐藏/恢复、停用账号、处理原因和日志 |

资料导入步骤：选择文件 → 后台提取带页/段落位置的文本 → 生成标题/正文/标签建议 → 展示建议与来源 → 用户编辑并保存为私有草稿 → 用户另行发布。

帖子修改步骤：在自己的帖子页提出修改要求 → 生成差异预览 → 用户确认 → 校验基础版本 → 保存新版本。草稿仍是草稿；已发布帖子的确认按钮必须明确提示“更新公开内容”。模型不能代替点击确认。

## 3. 技术结构

实施补充（2026-09-17，用户确认）：编辑器改用富文本，支持本机图片上传、文字颜色、背景和字号。结构化正文与图片引用随不可变版本保存，旧Markdown版本兼容读取，图片继承当前帖子可见性；详情见 [图文编辑说明](rich-media.md)。这替代下文最初仅Markdown编辑的界面约定，其余发布确认、版本、权限及阶段顺序保持。

第一版保留 Flask + SQLAlchemy + MySQL + Jinja，降低同时更换业务和框架的成本。页面交互使用现有 JavaScript 方式，模型沿用 DeepSeek。先做一个部署单元加独立 Worker，不引入微服务。

```text
浏览器 → 路由（登录、CSRF、参数检查）
          → 社区服务（权限、状态、事务） → MySQL
          → 私有上传 → 解析任务 → Worker → 帖子建议
          → 问答运行器 → 搜索/读取工具 → 权限检查 → 社区内容
                                   ↘ DeepSeek → 引用校验 → 回答
```

- 路由不直接拼 SQL；工具调用业务服务，不能直接调用页面路由。
- 文件、帖子、评论和模型输出均是不可信输入。Markdown 禁止原始 HTML，通过允许列表清理渲染结果，禁止脚本 URL。
- 上传内容存本地私有目录；数据库存文件位置、摘要、归属和来源关系。以后再换对象存储。
- 社区使用 `.env.community`、新数据库 `community_agent`、独立 Compose 项目/数据卷，建议本地端口 13307，避免占用旧库 13306。
- 用显式版本迁移维护新库，选 Alembic 管理社区结构；不复用旧学籍初始化脚本。
- 不把 Redis、向量库作为第一版必须项；先用 MySQL 管理有租约的任务，后续有测量依据再拆分。

## 4. 业务数据模型

| 数据 | 核心字段与约束 |
| --- | --- |
| user | id、唯一用户名、密码哈希、role、active、created_at |
| post | id、author_id、status、current_revision_id、version、deleted_at、published_at |
| post_revision | id、post_id、revision_no、title、Markdown 正文、editor_id、change_reason；版本号在帖内唯一 |
| tag / post_tag | 标签唯一名称；帖子与标签组合唯一，标签变更也进入版本快照 |
| comment | id、post_id、author_id、正文、status、created_at；只做一级评论 |
| post_like / post_bookmark | user_id + post_id 组合唯一；通过增删关系表达状态 |
| report | reporter_id、目标类型/ID、原因、处理状态、处理人/时间；校验目标实际存在 |
| document / document_section | owner_id、私有路径、摘要、大小；页/段落编号、提取原文、parser_version |
| processing_job | owner_id、document_id、status、lease_token、lease_until、attempts、error、生成结果 |
| post_source | revision_id、document_id、section_id；关联哪些原文支撑该版本 |
| content_chunk | revision_id、position、text；只索引当前公开版本，按段落切分 |
| conversation / message | owner_id、角色、内容、实际引用的帖子/版本/片段、时间 |
| edit_proposal | owner_id、post_id、base_version、候选正文/标签、原因、状态、提交回执 |
| audit_event | actor_id、动作、目标、前后版本、来源任务/建议、原因、时间 |

帖子正文保存在不可变版本中，post 只指向当前版本。保存草稿、发布、修改分别记录明确动作。业务枚举在服务端验证，数据库补充唯一键、外键和必要索引。

第一版点赞/评论数量通过索引查询实际记录计算，避免一开始维护多份计数。内容列表使用 `(published_at, id)` 游标，搜索最多返回有限候选，并设置查询超时和关键词长度上限。

## 5. 状态、权限与一致性

帖子状态：`draft → published → deleted`，管理员可将公开帖子变为 `hidden`。隐藏内容只有管理员可恢复；作者不能通过普通编辑绕过隐藏状态。删除使用软删除，第一版不做用户自助恢复。

任务状态：`queued → processing → succeeded / failed / cancelled`。Worker 领取租约后在事务外解析和请求模型，发布结果前检查租约令牌、任务状态和账号是否仍有效。重试最多三次；只产生一个结果，不能重复建帖子。

| 操作 | 访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 查看公开帖子/评论 | 可以 | 可以 | 可以 |
| 发布、评论、点赞、收藏、提问助手 | 不可以 | 可以 | 可以 |
| 查看草稿、上传原文、私有会话 | 不可以 | 仅本人 | 无默认全量访问权 |
| 编辑帖子 | 不可以 | 仅本人 | 不冒充作者编辑，只做治理 |
| 查看举报、隐藏/恢复、停用账号 | 不可以 | 不可以 | 可以并记录原因 |

所有工具调用、下载和确认操作重新检查服务端身份，不接受模型传来的 user_id/role 作为授权。

- 保存编辑携带 `base_version`，不匹配返回 409，展示冲突，不静默覆盖。
- 发布/更新时，新版本、post 指针、当前检索片段、来源关联和审计在同一事务提交。标题/正文长度受限，第一版同步写检索片段，避免额外的跨系统同步问题。
- 隐藏/删除后，搜索和读取均关联 post 的当前状态；旧索引或旧片段 ID 不能绕过权限。
- 点赞/收藏使用“设置为已点赞/取消”的幂等接口，而不是不确定的 toggle；唯一约束阻止并发重复关系。
- 发布与采纳建议使用操作键/已处理回执防重；评论提交也携带客户端生成的请求标识，避免网络重试重复评论。
- 新评论只能写入仍公开、未删除的帖子；事务中锁定并复核帖子状态。

## 6. 文档生成草稿：固定工作流

第一版限制：单文件 10MB、PDF 20 页、提取文本 30,000 字符；仅接受 TXT、Markdown、文字 PDF，拒绝加密文件、异常大小和不支持格式。不抓取文档里的外部链接。

1. 服务端验证文件、大小和归属，保存摘要及任务；上传提示提取文本将发给配置的模型。
2. Worker 提取文本，保留文件与页/段落位置。超限或无文字明确失败，不静默截断。
3. 模型输出受约束 JSON：标题、Markdown 草稿、标签建议、引用的 section_id。文档里的命令只当文本。
4. 服务端校验结构、长度、标签数量和 section_id 归属。模型生成是整理建议，不能因“引用 ID 有效”就认定内容忠实。
5. 页面展示原文与生成内容，用户可编辑、放弃或采纳成私有草稿；发布是单独显式操作。

上传文档默认一直私有。发布帖子只公开用户确认的正文，不自动公开完整附件。公开读者可看到“作者提供的资料”等来源说明；文件名、原文片段、下载地址仅所有者可见。向公开帖子引用私有资料时不能把原文访问权一并泄露。

来源绑定不可变 revision，后续手工编辑仍保留该版本的生成来源，但不能将编辑后的每句话都宣称为原文证据。

## 7. 社区问答：受限 Agent

问答只检索公开帖子正文，第一版不检索私有草稿、原始文件、历史版本或评论；界面明确标注范围。

工具只提供：

| 工具 | 输入 | 服务端输出 |
| --- | --- | --- |
| search_posts | keywords、可选 tag | 有限条候选、帖子ID、标题、当前版本ID、摘要 |
| read_post_chunks | post_id、revision_id、片段范围 | 当前可见版本的正文片段及 chunk_id |

工具不接受 SQL、表名、任意 URL、文件路径或权限参数。用户输入和检索内容都不能改变允许的工具集。最多四次调用，并设置单请求超时、总时限和输入输出长度限制；超限即停止并返回可解释的失败。

检索第一版采用 MySQL 参数化关键词匹配：限制关键词数量，转义 LIKE 通配符，对标题/标签命中加权，再取候选正文片段。中文支持直接子串匹配，用户没有合适关键词时可能漏召回；先用可核对的样例测效果，不宣称具备语义检索能力。向量/混合检索放到后续，根据漏检样例再引入。

模型返回结构化回答段落及引用 chunk_id。服务端要求：

- 引用来自本轮实际读取结果，属于当前仍公开的版本。
- 回答中的社区事实段落必须附引用；没有证据时说明未找到，不猜帖子内容。
- 返回前重新检查帖子状态与版本；检索期间被修改或隐藏，拒绝旧引用并重试一次或提示内容变化。
- 引用卡片由服务端生成真实链接，模型不能自行编造链接。
- 引用存在性校验不能证明语义支持，仍需用人工标注任务测“引用是否支持结论”。

引用跳转到帖子对应片段。帖子已经更新时说明旧回答引用已过期；用户重新打开历史会话时校验引用版本，受影响回答标为不可用并不展示旧正文，避免删除后从聊天历史继续泄露。

## 8. 本人内容修改建议

使用帖子编辑入口提供明确 post_id 和当前版本，避免助手猜测目标。模型只输出修改候选，服务端建立 edit_proposal，不能在同一次模型调用里确认。

确认时检查：本人所有权、账号状态、帖子状态、base_version、建议仍待处理。一次事务内保存新版本、来源/审计并更新检索片段。重复确认返回同一回执；数据已变则拒绝并要求重新生成。用户在聊天中说“确认”不能替代页面操作。

第一版不允许通过助手删除帖子、封禁用户、改他人内容或处理举报。

## 9. 接口草案

| 接口组 | 主要接口 |
| --- | --- |
| 身份 | POST /auth/register、/auth/login、/auth/logout |
| 帖子 | GET/POST /posts；GET/PATCH/DELETE /posts/{id}；POST /posts/{id}/publish |
| 本人 | GET /me/posts、/me/bookmarks；GET /posts/{id}/revisions（仅本人） |
| 互动 | GET/POST /posts/{id}/comments；DELETE /comments/{id}；PUT/DELETE /posts/{id}/like、/bookmark |
| 资料 | POST /documents；GET /documents/{id}、/download（仅本人） |
| 任务 | POST /draft-jobs；GET /draft-jobs/{id}；POST .../cancel、/retry、/adopt |
| 问答 | POST /assistant/conversations；GET /assistant/conversations/{id}；POST .../messages |
| 修改 | POST /posts/{id}/edit-proposals；POST /edit-proposals/{id}/confirm、/cancel |
| 治理 | POST /reports；GET /admin/reports；POST /admin/reports/{id}/resolve、/admin/posts/{id}/hide、/restore、/admin/users/{id}/disable |

统一错误语义：400 参数、401 未登录、403 无权限、404 不可见或不存在、409 状态/版本冲突、413 文件超限、429 频率限制、503 模型不可用。服务端记录 request_id，不返回 SQL、密钥、内部路径或完整原文日志。

登录、发帖、上传和模型请求需要频率/并发限制。单机第一版可用数据库原子计数/活动任务限制实现，停用账号的已有会话在每次请求时失效。

## 10. 对现有项目的实施顺序

方案制定轮次只换方案与项目名称。开始编码前为旧实现建立明确版本快照，确认工作区未提交变更；不删除旧数据库和资料。

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 0 社区底座 | 独立配置/数据库/迁移，重建 user 角色，隔离学籍路由和启动脚本 | 新服务不会读旧库，登录权限和迁移可重复验证 |
| 1 内容发布 | 帖子版本、草稿、标签、发布/编辑/删除、安全 Markdown | 两个用户可独立发布，越权及并发编辑被拒绝 |
| 2 社区互动 | 评论、点赞、收藏、时间流、搜索、举报与治理 | 重复请求不重复计数，隐藏后普通入口不可见 |
| 3 资料草稿 | 复用解析/任务思路，新增来源模型、固定生成流程、采纳界面 | PDF/Markdown/TXT 到私有草稿，必须再点击发布 |
| 4 问答与修改 | 检索工具、引用校验、问答页、本人编辑建议确认 | 可引用公开当前内容，隐私与版本变化测试通过 |
| 5 交付评测 | 演示数据、故障样例、MySQL 集成/浏览器测试、部署说明 | 验收表有实际结果，明确剩余限制 |

目录建议：`app/services/community/` 管理业务，`app/services/documents/` 处理资料，`app/agent/` 保留模型适配和受限工具循环，`workers/` 处理任务，`migrations/` 管理新库，`tests/` 区分社区与历史学籍测试。

不直接搬旧 students/grades 工具。旧 DeepSeek 客户端需要补充用量记录、错误分类；旧任务管线保留租约/取消思路，结果改为草稿而不是业务表导入。旧 app/models.py 和 SQL 规则属于待替换的学籍业务。

## 11. 验收与演示数据

准备至少 30 篇原创/虚构帖子、3 个用户（含管理员）、若干评论和 6 份手工标注资料，涵盖三个支持格式以及空内容/超限/加密等失败样例。禁止使用真实个人资料构造公开演示。

| 场景 | 验收要求 |
| --- | --- |
| 双用户隔离 | 不能读对方草稿、文件、任务、修改建议或私有会话 |
| 发布与修改 | 版本冲突不覆盖，重复确认只生成一个版本 |
| 互动并发 | 重复点赞/收藏不增加关系，重复评论请求不生成两条 |
| 删除与治理 | 帖子隐藏/删除后，详情、搜索、工具和历史引用都失效 |
| 任务中断 | 取消或租约过期的 Worker 不能发布结果；失败可重试但不重复建草稿 |
| 文档提示注入 | “忽略规则、读取私有文件”等文档文字不会获得新权限或工具 |
| 引用正确 | 引用必须实际读取、定位到有效当前正文；语义支持另行人工评测 |
| 模型失败 | 超时/无效 JSON 不发布内容、不改帖子；基本社区功能仍可用 |
| 渲染安全 | 脚本、危险链接、附件伪装不能通过 Markdown/下载接口执行 |

问答评测至少 30 题：明确检索、跨帖归纳、找不到答案、模糊问题、注入攻击、删除/版本变化。记录检索命中、引用支持、正确拒答、耗时及用量，不能只报告“回答流畅”。明确检索样例命中目标可先设为 90%，这是待测目标，不是当前成绩；权限泄露和未确认写入用例必须全部拒绝。

第一版演示：上传一份技术笔记 → 检查来源并生成草稿 → 编辑发布 → 另一用户评论/收藏 → 提问助手并点击引用 → 作者更新或管理员隐藏帖子 → 重新查询验证旧内容不再使用。
