# P3：Harness、模型适配与本地对话

日期：2026-09-20。P2复核通过。P3工程实现及离线/浏览器验证已完成；**真实模型验收待配置，暂不把P3整体标为验收完成**。

## 当前可用内容

启动 `start.ps1` 后访问 **http://127.0.0.1:8080/#assistant**，也可从原网页顶部“社区研究助手”进入。

界面支持新建和切换会话、提问、查看目标整理与执行记录、停止本轮、阅读带引用回答。点击引用后查看本地原文、评论所属帖子和父评论上下文，自动滚动至高亮片段；“返回刚才的对话”回到同一会话。会话、用户问题和回答持久化，刷新后恢复。

历史会话用内容主题命名：优先提取既有计划中的主题，合并最多3个不同主题并限制30字符；尚无计划时压缩首条问题作为标题，空会话显示“新对话”。已有会话自动适用，不新增模型调用；列表不再展示编号与时间戳。

展开“选择对话”后，每个会话标题右侧有“×”，可直接删除该项，无需先切换到它；确认框显示具体标题。删除在事务内清除该会话的目标修订、提问、回答、运行、事件与诊断记录，不删除采集来源、帖子/评论、其他会话或共享证据。运行中的会话需先停止并等待结束；后端同样拒绝运行中删除。删除当前会话后清理选中状态，删除其他会话不改变当前会话。接口为 `DELETE /api/research/sessions/{id}`。

会话切换和URL同步由同一入口更新；异步列表和详情响应带前端版本检查，旧响应不能覆盖新操作。轮询串行执行，请求最长15秒，创建/发送/删除共用同步互斥标记，防止快速双击重复提交。浏览器回归包含延迟2.5秒的旧列表、重复点击、三轮创建删除、非选中项删除、切换、已删除链接恢复及390px窄屏菜单。

删除确认使用页面内弹窗；点击×立即收起会话列表，删除成功、失败或取消后将焦点归还提问框。点击列表外部或聚焦输入框也会关闭列表，避免悬浮层挡住输入。回归通过真实鼠标点击和键盘输入验证，不以程序直接填值替代可交互性检查。

引用针对本地采集快照。网站原帖在新标签页打开；不承诺原站页面仍存在或能准确定位其评论。源文件失效时旧回答显示失效提示，不再作为后续模型上下文。

来源展示采用独立内容卡片，替代“原文1.1”一串编号。帖子显示采集到的标题、已引用原文节选与网站原帖链接；评论显示原文节选、所属帖子标题/网站链接，以及单独的“查看评论原文与上下文”。标题和链接由后端从有效来源生成，不相信模型自由生成的标题/URL。相同实体的多个片段合并，明确显示本次引用了几个帖子/几条评论，与模型段落数、全部检索命中数区分。旧会话刷新后也使用卡片，不改写历史回答。模型规则要求新回答逐条概述，最多50段，仍受调用与输出预算限制。

标题链接下显示原帖发帖时间（原始来源时间）和“回复数（采集时）”。评论卡片使用所属帖子的这两项数据，不把评论发布时间当发帖时间。回复数来自原文件total_replay_num，不是本地已采集评论数量，也不保证网站实时数量；缺失时显示“未采集”，真实0保留。计数保存在独立record_metadata表，不纳入内容快照哈希；旧文件可幂等重新导入补齐，无需重新访问网站。

这一阶段仍然只查询本地已导入数据。通过对话直接上贴吧搜索、自动补采和导入属于P4；底层仍会复用当前Harness和P2工具。

## 模型配置

配置位于项目根目录 `.env.research`。字段格式如下（真实密钥不写入文档）：

```dotenv
RESEARCH_BASE_URL=https://你的服务商地址/v1
RESEARCH_API_KEY=你的密钥
RESEARCH_MODEL=该服务商实际支持的模型名称
```

BASE_URL 应为 chat-completions 兼容接口的基础路径，程序在其后追加 `/chat/completions`，不要重复填写该后缀。`/v1` 是否需要由供应商地址决定。远端必须HTTPS，localhost/127.0.0.1/::1可用HTTP。环境变量优先于文件；每轮重新加载配置，填写后无需重启。密钥不发送到前端、不进入工具上下文或数据库。

当前适配器使用常规messages请求和受校验的JSON动作协议，不要求原生function calling。DeepSeek官方域名额外启用response_format=json_object、thinking=disabled；其他供应商不默认发送这些可选参数。支持完整JSON代码围栏，拒绝猜补残缺内容。finish_reason=length、空响应和JSON语法错误分别报告，安全诊断只保留长度和错误位置，不保存原始输出。模型实际质量仍需独立验收。

仅配置完整时前端显示已配置；这不等于已验证服务可达或模型名称有效。认证失败、限流、连接失败、请求被拒绝、服务错误、响应格式错误和超时分别返回错误码，不伪装成没搜到帖子。

## 模块分工

| 模块 | 职责 |
| --- | --- |
| `agent/model.py` | 读取配置，发送模型请求，限制响应大小并分类错误 |
| `agent/runtime.py` | 会话目标/执行持久化、模型循环、工具白名单、预算、取消、引用校验 |
| `knowledge/search.py` | P2真实检索和证据读取，不依赖模型 |
| `api/router.py` | `/api/research/*` 会话、运行、取消、引用阅读接口 |
| `ResearchAssistant.tsx` | 会话和证据界面；不承担工具权限与预算检查 |

循环为：原始目标/最近对话 → 模型整理计划 → 调用只读工具 → 读取证据 → 提交结构化回答。

用户原文作为每轮独立目标修订保存；模型计划存到另一个字段，不能覆盖原文。原始目标作为历史起点，最近8轮历史按user/assistant角色和时间顺序传递，最后追加当前问题；用户明确换题或修正时以最新要求为准。失效回答只保留不可用状态，不传回旧正文。查询表达不能修改目标记录。歧义词要求澄清；澄清结果进入waiting_user，用户补充后产生新run和新目标修订。当前不是无限长期记忆，也不重放旧工具原文；领域理解与语义漂移仍需真实模型评测，不能靠保存目标记录保证语义正确。

## 运行约束

- 默认每轮最多8次模型调用、10次工具调用、90秒总时限、单次模型30秒；API可降低预算，不接受模型扩大预算。上下文最多100000字符，每次输出请求上限4096 tokens。
- 只允许 search_posts、search_comments、read_evidence。写入、删除、任意URL访问和采集动作均不在模型工具白名单中。
- 模型可先提交计划，也可对明确追问直接调用只读工具；直接调用时系统记录本轮请求范围，不冒充模型语义总结，工具参数仍由P2校验。错误动作/JSON/引用只有一次纠正机会，消耗同一预算。当前不自动重试网络请求。
- 可读取本轮工具返回的ID，或同会话最近历史回答中仍有效的引用ID；历史ID只是允许重新读取，不自动算本轮已读。事实段落必须引用本轮实际读取且仍有效的证据，跨会话ID不因此开放。引用存在与偏移正确不证明语义结论成立。
- 历史助手回答使用规范answer结构，避免用另一套JSON包装误导后续动作。仅对确定的缺action答案和三个只读工具简写做规范化，其余未知动作仍拒绝；一次输出多个对象仍要求模型纠正。诊断只保留已知字段存在性及JSON错误类别，不记录自由文本。
- no_matches需本轮有成功的空检索且没有正结果；工具异常不能被当成无结果。范围始终标为local_imported_data。
- 同会话不允许重叠运行，其他会话可独立执行。取消终止后续模型调用；正在执行的本地只读线程可能完成当前查询，不会开始爬虫或外部写操作。
- 服务重启把未结束run标为interrupted，不自动恢复或重置预算继续跑。模型格式、服务错误和预算耗尽会持久化具体失败原因。
- 工具事件只保存工具名、状态、耗时、数量、证据ID，不保存Cookie、密钥或全量工具原文。模型往返原文仅在本轮内存中；用户问题和最终回答按会话保存。
- SQLite研究表与P1/P2数据库共存。本地单进程服务使用，暂不支持多Web worker或跨进程分布式运行。

## HTTP入口

- `GET /api/research/config`：只返回配置是否齐全、模型名与本地范围。
- `GET/POST /api/research/sessions`：列举/创建会话。
- `GET /api/research/sessions/{id}`：恢复会话及运行记录。
- `POST /api/research/sessions/{id}/runs`：`{"text":"问题","budget":{"model_calls":8,"tool_calls":10,"seconds":90}}`，返回run_id。
- `GET /api/research/runs/{id}`、`POST /api/research/runs/{id}/cancel`：查看/取消。
- `GET /api/research/runs/{id}/evidence/{evidence_id}`：只允许该回答引用的证据，返回原文窗口及相关上下文；失效返回410。

模型层与HTTP层独立，测试可注入脚本模型；生产入口始终使用配置中的ChatModel，没有偷偷回退的演示模型。
