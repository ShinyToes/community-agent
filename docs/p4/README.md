# P4：在线采集调度与自动问答

> 以下保留P4阶段的计划确认交付记录。当前界面已升级为默认预算自动执行，不再显示模式选择或必经确认表单；请按[P5使用说明](../p5/README.md)操作。旧待确认计划不自动补跑，`check_p4_ui.py`已转发到新版自动助手界面测试。

此前的会话、证据卡片、原帖时间和回复数展示属于 **P3 的完善**。P4 在其基础上接入现有 MediaCrawler，不重新实现贴吧爬虫。

## 使用方式

打开 `http://127.0.0.1:8080/#assistant`，输入自然语言问题：

1. 在输入框旁选择“查询已有数据”或“联网采集（贴吧）”，直接描述需求并点击统一的“发送”。页面记住上次选用的模式；首次默认查询已有数据。
2. 联网模式由模型自动生成最多 3 个保守查询，不需要用户填写关键词。界面展示生成的查询词和本地帖子命中情况。
3. 查看预算，点击“确认计划并采集”。查询词可通过“调整查询词（可选）”修改，不改也可以直接确认。制定计划本身不会启动爬虫。
4. 必要时在打开的贴吧浏览器扫码登录，系统继续采集、导入并回答。等待登录和回答都计入总时限。
5. 查看帖子标题、网站原帖链接、采集时回复数、发帖时间和本地证据；刷新后保留计划及回答。

当前在线入口只支持贴吧、二维码登录或已有浏览器登录态；原采集页其他平台与登录方式保持原有入口。助手不读取或接收 Cookie。

2026-09-21：首页默认进入助手；原爬虫配置保留为顶部“高级手动采集”，兼容原 `#crawler` 地址。独立“制定在线采集计划”按钮已由模式选择和统一发送替代，尚未引入 P5 的语义别名扩展。新版隔离浏览器 15 项检查通过，覆盖自然语言请求不携带手填查询词、改词可选、模式记忆、本地发送不启动爬虫和高级采集往返。

## 实现与边界

- `agent/collection.py`：持久化计划、预算、分支、任务来源和回答关联，管理确认、执行、等待登录、导入、回答、取消、超时和部分完成。
- `MediaCrawler/api/research_bridge.py`：唯一爬虫适配入口，使用原有任务创建、状态、输出和进程停止功能；只返回结构化状态及文件路径，不把原始日志或 Cookie 交给模型。
- `api/router.py`：计划与执行接口；采集期间同会话拒绝新问答和删除，整个采集链占用爬虫，防止与手动任务交错。
- `CollectionPanel.tsx`：计划编辑和执行状态；确认按钮防重复，计划 ID 是幂等键，已执行计划不能偷偷改预算。
- `Harness`：导入完成后，携带本次来源及采集范围运行原有只读检索/读取/引用循环。最终仍需实际读取证据才能引用。

默认每查询 5 帖，最多 3 个查询、每查询 20 帖；补评论默认 0 帖、最多 5 帖，每帖最多 20 条一级评论，不采楼中楼；总时限 30–300 秒，默认 180 秒。规划最多 1 次模型调用，回答继续使用 P3 的最多 8 次模型调用和 10 次工具调用。

先采候选帖子，再从标题/正文包含该查询所有空格分词的帖子中，按发现顺序挑选预算内的帖子补评论。**这是有界字面筛选，不是 P5 的语义相关性核验**。例如 `CS 饰品` 可以分开匹配，`CS饰品` 仍要求连续出现。平台返回的其他帖子也保留原始来源，不伪装成相关命中。

修复了贴吧搜索原来把小于 10 的帖子上限提升到 10 的行为；搜索结果按剩余配额截断、同分支去重。助手任务不额外抓取配置文件中的贴吧列表，避免超出批准查询范围。

## 失败与恢复

- 普通取消和超时调用原爬虫停止流程；Windows 停止进程树。已导入的完成分支保留。
- 助手任务的自动登录入口选择器失效时，保持浏览器并等待手动登录；不绕过验证码或平台验证。未完成登录就退出、以及登录等待超时分别显示明确原因。
- 当前分支中途取消/超时形成的文件保留在任务目录，暂不自动导入；可在数据管理检查，再显式导入。不能把它当成完整采集。
- 服务重启将未完成研究计划标为中断，不自动重跑。强制杀死 Web 进程后，若旧爬虫仍存活，原任务保护会阻止新任务；此异常恢复不等同于正常取消，仍需确认旧进程已经停止。
- 一条查询失败但已有可导入结果时，保留部分数据并标明部分完成；无文件不会伪造“已检索且没有帖子”的答案。
- 新采集的来源可随原有“数据管理”删除而失效，历史引用继续使用 P1/P3 的失效检查。删除会话不删除采集文件。
- 不保证全站覆盖；自动别名发现、主题相关性判断和增益驱动扩展仍属于 P5。

## 验证

2026-09-20：P3 基线 106 项测试、25 项浏览器检查、既有数据分页与 58 个原文片段复核通过。P4 增加后联合测试 123 项通过；前端 TypeScript/生产构建通过；真实爬虫搜索逻辑在隔离响应下验证 1、11、20 帖配额及参数传递；P4 浏览器 9 项检查通过，JavaScript 错误为 0。

隔离测试使用真实导入、检索、Harness 和 HTTP/UI，爬虫响应与模型输出为替身，不代替实际平台验收。实际平台测试结果另记录在 `live-validation.json`；若需要扫码，不能把等待登录或超时称为在线闭环通过。

首次真实测试中，模型成功生成 `donk` 查询计划，但贴吧二维码未出现，旧登录按钮选择器点击超时，任务退出且没有文件，见 `live-first-attempt.json`。随后增加了选择器失效时的手动登录等待，并通过隔离验证。

修复后真实闭环复测通过，见 `live-validation.json`：模型规划 1 次；贴吧实际采集 1 帖、0 评论；自动导入 1 个来源；回答阶段模型 3 次、工具 2 次，状态 completed，引用有效。抽查标题、原帖链接、发帖时间、回复数 270 和正文切片与保存的原始文件一致；回答正确将正文表述为发帖人的转述，未当成已证实事实。此结果证明最小在线闭环可用，不代替系统性语义质量或所有登录状态验收。

真实 Windows 取消检查通过，见 `live-cancel-validation.json`：捕获 13 个采集及浏览器进程，取消后等待操作系统退出 2 秒，残留 0，爬虫恢复 idle。取消检查只删除其自行创建的临时会话，采集任务记录保留。
