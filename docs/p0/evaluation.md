# P0 评测与样例基线

固定集合见 fixtures.json。全部为虚构文本，不代表 donk 别名已获得事实认证。20 个用例由 P1/P2/P3 分别落实，P0 只校验材料完整性和明确的字面预期，不宣称这 20 项功能测试已经通过。

## 真实数据核对基线

- R01：testresult 帖子 40 条、评论149条，自身 ID 均无重复；15 个不同原帖 ID 在该帖子文件缺失，不能按日期强配。
- R02：源采集任务 a6e6f4dae188490988db1084677f423d 的输出为20条帖子、149条评论，目录内评论原帖关联无缺失；实际状态 stopped，覆盖应标记部分而非完整。
- R03：另一个 B站任务状态 stopped，无本次可盘点帖子/评论文件；M1 不支持平台 bili，应返回明确的 unsupported_platform，不能生成空贴吧任务。
- R04：无时区发布时间必须按来源指定的时区转换；last_modify_ts 不用于判断帖子发布时间。

这些数字是2026-09-20本地文件盘点结果，复测前先比较 data-inventory.json 的哈希。数据变化后重建基线，不盲目套用旧数量。

## 分层验收

1. P0 材料校验：JSON可读、ID唯一、引用的样例存在、五个字面检索预期符合指定规则、文档链接存在。检查脚本不是产品检索器。
2. P1/P2 工程验收：对照固定用例执行实际模块测试；确定性必需行为全部通过才能进入下一里程碑。增加坏字段、越界路径和索引失效故障用例。
3. P3 模型验收：用真实模型检查 E16–E18，记录模型配置、读取证据、最终引用、错误与用量；人工逐条标“支持/不支持/不确定”，没有核对的条目标未评审。
4. 浏览器验收：独立测试数据中完成 E19，禁止删改用户采集数据来制造测试结果。

本轮未运行真实模型，也未获得人工标注的相关性成绩。先报告每个用例结果，不预设全平台召回率。P5 再加入更大的人工相关性集合，比较正式名称、固定扩展、自适应探索的覆盖、误检、漂移和成本。
