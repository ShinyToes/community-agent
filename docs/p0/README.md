## 范围决定

- M1 只处理本地贴吧数据，导入 JSON 数组和逐行对象 JSONL，提供帖子/评论条件检索、证据阅读、带引用问答。
- 先支持已结束任务；运行中任务不自动导入，避免读取半写文件。失败/停止任务可显式导入，但必须标记部分结果。
- Excel、CSV、其他平台、在线采集调度、自动别名扩展和向量检索不进入 M1。
- 本地单用户、一个 Web 进程；使用 SQLite 存索引与状态，保留原始文件，不新建 MySQL 或分布式服务。
- 模型供应商尚未接入或选定。P3 在独立适配层配置，不读取已删除旧项目的密钥。
- 规则和 ID 校验可以确定性验收；语义相关性和回答是否忠实需要人工核对，不能宣称已获得准确率。

## 真实样例盘点

读取范围限于 `testresult/` 与 `MediaCrawler/data/` 中的帖子、评论及任务元数据，不读取 Cookie、浏览器登录目录或日志。

- `testresult/search_contents_2026-09-18-1.json`：40 条帖子、40 个唯一 ID；2 条 `desc` 为空。来源关键词为编程副业、编程兼职、cs、cs饰品，各 10 条。
- `testresult/search_comments_2026-09-18.json`：149 条评论、149 个唯一 ID；2 条空内容。149 条 `parent_comment_id` 均为空，不能据此验证子回复链。
- 这份评论文件的 15 个不同 `note_id` 在 `testresult` 帖子文件中不存在。两份文件不能当作完整配对数据集。
- 评论没有 `source_keyword`；仅有原帖 ID 时不能推断来自哪个关键词或任务。
- 采集目录另有一个已停止的贴吧任务：20 条帖子、149 条评论，该目录内评论均有对应原帖。因此 testresult 的缺失是这份样例配对不全，不能直接判定采集器漏抓正文。另有一个已停止的 B站任务，无本次可盘点输出。
- 时间字符串没有时区；当前 `tools/time_util.py` 使用本机 `time.localtime`，导入时不能直接当 UTC。
- `last_modify_ts` 是采集记录更新时间，不等于原帖最后编辑时间或任务开始时间。
- `creator_hash` 与脱敏昵称不是稳定、可验证的平台账号身份，M1 不承诺按它还原用户或查询其全部活动。

完整文件哈希、当前采集目录数量和任务状态以 `data-inventory.json` 为此次盘点快照。原文件以后变化需重新盘点，不按文件名认定字节内容未变。

## 现有与新增能力边界

现有采集启动、取消、任务元数据、独立输出、数据预览和删除可作为 P4 适配基础。当前没有统一知识索引、版本化证据库、目标记录、Agent 循环或语义验收机制。

当前服务的 `max_notes_count` / `max_comments_count` 可为 null，元数据不一定保存有效默认上限；不能据此推导真实覆盖。P4 必须核对平台实际执行数量，而不仅检查参数提交成功。

本次文件检查没有找到 `MediaCrawler/.git`，`git diff` 无法运行；此前“保留独立 Git 历史”的记录不能当作当前事实。P0 不初始化、修复或覆盖 Git 元数据，后续开发前需单独确认版本管理布局。

## 决策与后续入口

P0 契约版本为 `0.1`。后续语义变化需同步契约和样例。下一步从 P1.1 的显式来源注册、格式校验和导入报告开始；先完成幂等与缺失关系处理，再建立检索。

复核命令（外层项目目录）：

```powershell
.\MediaCrawler\.venv\Scripts\python.exe tools/audit_p0_data.py
.\MediaCrawler\.venv\Scripts\python.exe tools/check_p0_materials.py
```

第一条重新生成盘点报告；第二条只校验设计材料和样例一致性，不执行采集、不调用模型、不创建索引。
