# 本地资料与有界工作上下文

2026-09-22 实施记录。

## 已接入

- 每个搜索分支导入后立即进行单帖核验，然后继续下一分支。原始帖子和评论全部保存在原有任务目录与知识库中，排除项也保留。
- 每次核验使用新的两条消息：任务规则，以及当前问题、语义范围、当前单帖的标题/正文预览与所属贴吧。不会提供其他候选的正文和判断。依据仍须逐字匹配本帖片段，模型返回后重新检查来源有效性。
- 单帖笔记按快照ID保存到采集任务的持久进度中，含实体ID、判断、理由、引用依据及核验状态。每条完成立即保存；重复快照不重复审阅，新快照重新核验。未审阅与无关分别计数。
- 默认最多8次独立核验，明确扩量最多12次；并发最多3，每次10秒，所有批次累计核验时间最多40秒，并继续服从全轮180秒总时限。额度耗尽的候选留作未审阅，不伪称完成筛选。旧版无semantic_scope的计划保留兼容路径。
- 最终本地候选列表优先使用本轮快照及单帖笔记，初筛无关的正文不默认送入汇总上下文；未审阅和待核实仍可继续读取。原始候选统计与工作候选数量明确区分，原文可再次检索。
- Harness每次工具动作后重新构造消息：用户目标和近期用户约束、简短会话摘要、预算、最近操作、至多100个可回读证据ID及最新工具结果。旧工具正文不继续叠加。用户问题保留原文，历史助手长回答仅保留明确标记的节选，不能当证据。
- SQLite新增research_working_steps，保存查询参数和结果引用。完整原文使用已有快照存储，不另存一份难以撤销的工具正文；read_evidence重读时仍检查来源失效。删除会话同时清理工作记录，不删除采集原文。

## 边界

已实现的是逐批持久化、独立单帖语义核验、本地候选回读和主动精简上下文。现有hybrid_search接口继续可用，但环境尚未配置嵌入模型；不能将聊天模型核验称为真实向量召回。

查询仍由初始规划生成，最多3个；本轮没有新增模型自动改写后续查询或无限探索。最多8/12个独立核验不等于其余候选被排除。片段不足、预算不足须保留待核实/未审阅状态。相关性初筛和提示约束不能保证杜绝错误归因；第13节完整的展示资格模型与误排质量评测仍需独立实施。
