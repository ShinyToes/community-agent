# 自动任务调度与语义检索基础（2026-09-21）

本轮交付是单一助手流程和P5的基础能力，不等于全部语义策略已通过系统性质量验收。

## 使用

打开 `http://127.0.0.1:8080/#assistant`，直接输入问题并发送。不再选择本地/联网，也不再填写关键词、数字预算或点击采集确认。

- “只看已有数据，不要联网：有哪些提到donk的帖子？”：走本地路径。
- “收集一些热门打分帖”：模型生成查询表达，自动采集并分析。
- “某款游戏最近口碑如何？”：内部识别评价任务；对象缺失且会话无法补足时先澄清。
- “多找一些”“只采一个帖子”“不采评论”：由内部策略映射到受限预算。

执行进度与输入框旁的停止按钮可见，具体查询词、预算和分支在“执行详情”中。旧待确认计划只作为历史记录，绝不因刷新、重启或升级自动执行。手动爬虫收进顶部“高级”菜单，返回后恢复原会话。

## 后台流程

新增 `agent/strategy.py` 定义结构化任务策略与分析规则。`CollectionService.start_automatic` 持久化用户问题后立即返回，后台完成理解、资料预览、数据路径判断、采集和回答，接口为 `POST /api/research/sessions/{id}/messages`，请求只有 `text`。

模型识别 lookup、reputation、reasons、comparison、popular 等内部任务；允许用户用会话澄清对象和目标。数据策略为local、online、auto或clarify。auto会读少量本地帖子/评论及时间与范围信息，再判断资料是否足够；已配置向量时也可查看一批混合候选。网页和历史回答均视为不可信材料，不作为指令。

结构校验、明确禁止联网的额外保护、采集独占、活动会话保护、取消与超时由服务端执行。分类与数据充分性仍是模型判断，不能保证每次正确；用户显式要求仅本地时应优先遵守，测试覆盖了直接禁止联网表达。

## 预算

- 默认最多3个查询，全轮最多20次帖子额度；明确要求扩大数量且能对应本轮原话时，上限40，每查询仍不超过20。
- 若需要评论，预留最多3帖、每帖20条一级评论。为保守约束实际工作量，补读原帖也占总帖子额度：例如默认20可分为17个搜索候选额度＋3个补读额度。相同帖子跨分支出现仍消耗额度，不靠去重绕过上限。
- “最多1帖”会减少分支数，避免每个查询各采1帖。不采评论的明确要求有额外校验。
- 总时限180秒，包含规划、预览、登录等待、采集与回答。规划最多2次尝试，auto资料判断再最多1次；回答保持最多8次模型、10次工具和90秒子预算。
- 数据不足、登录失败或时限结束不冒充无结果。不会保证用满预算或找齐全站内容；“多找一些”表示扩大允许额度，不承诺一定获得更多相关内容。

## 分析与检索

已有：常见写法变体及问题方向的查询生成；评价、原因、变化比较与热门内容的内部分析规则；证据核验和原帖统计读取。`read_evidence`新增`post_stats`，让模型看到采集时回复数与发帖时间，避免把“没采评论正文”等同于“没有回复数”。热门候选补评论前可按已采回复数排序，结论仍限于实际候选范围。

新增可选`hybrid_search`：字面检索与向量候选合并，模型仍必须读取原文核验。向量缓存基于快照、字段片段、接口与模型身份；源数据失效时清理，外部嵌入请求结束后再次验证来源。近似候选不作为全量命中计数，相似度不证明相关性或别名同一。

当前采用小规模SQLite向量缓存与进程内相似度计算。每次最多考察200个片段、补嵌入32个片段，与查询向量合并为一个请求；会明确返回部分覆盖。原文按800字符切片、600字符步长，保留位置及帖子/评论关系。接口失败返回错误；未配置时仅进行明确标记的字面回退。
